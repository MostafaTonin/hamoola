# قرار معماري 006 — استراتيجية النشر (Deployment)

**الحالة:** مقترح  
**التاريخ:** 2026-09-25

---

## السياق

مشروع حمولة يحتاج لاستراتيجية نشر واضحة تضمن انتقال الكود من بيئة التطوير إلى الإنتاج بشكل آمن وموثوق وقابل للتكرار. الهدف هو بناء Workflow احترافي من البداية يمنع النشر اليدوي الخطأ ويضمن جودة الكود.

---

## القرار

نعتمد **GitHub Actions** كأداة CI/CD أساسية لأتمتة عمليات البناء والاختبار والنشر.

**هذا القرار مقترح** — اختيار الـInfrastructure النهائية (VPS، Managed Cloud، Azure، AWS، DigitalOcean، إلخ) **لم يُحسم بعد** وينتظر:

1. اكتمال تصميم معمارية الـBackend.
2. تحديد متطلبات الأداء والموثوقية.
3. تقييم تكاليف الاستضافة.

---

## ما تم الاتفاق عليه (معتمد)

### مبادئ النشر الأساسية

1. **لا نشر يدوي على Staging أو Production** — كل نشر يمر عبر Pipeline آلي.
2. **كل Merge على `main` يُشغل Pipeline** تلقائياً.
3. **Tests تمر قبل أي نشر** — إذا فشل أي Test لا يتم النشر.
4. **النشر على Production يحتاج موافقة يدوية** (Manual Approval) حتى لو نجح الـPipeline.
5. **Rollback جاهز** — يجب أن تكون آلية التراجع السريع (Rollback) متاحة دائماً.

---

## Workflow المقترح (CI/CD)

```
Push / PR على GitHub
        ↓
[CI] تشغيل الاختبارات تلقائياً
        ↓
[CI] تحليل الكود (flutter analyze / dotnet build)
        ↓
[Merge على main]
        ↓
[CD] نشر تلقائي على Staging
        ↓
[موافقة يدوية]
        ↓
[CD] نشر على Production
```

---

## ما هو غير محسوم (قيد الدراسة)

| العنصر | الحالة |
|---|---|
| اختيار Cloud Provider (Azure / AWS / DigitalOcean / VPS) | قيد الدراسة |
| Container Strategy (Docker / Kubernetes) | قيد الدراسة |
| Database Hosting (Managed / Self-hosted) | قيد الدراسة |
| CDN وتوزيع Assets | قيد الدراسة |
| Monitoring وAlerting (Application Insights / Grafana / Sentry) | قيد الدراسة |
| Secret Management (Key Vault / GitHub Secrets) | قيد الدراسة |

---

## الآثار

- يجب إنشاء ملفات GitHub Actions في `.github/workflows/` عند بدء تطوير الـBackend.
- كل بيئة لها Pipeline مستقل أو مرحلة (Stage) مستقلة في نفس Pipeline.
- Secrets وبيانات الاعتماد لا تُوضع أبداً في الكود.

---

## ملاحظات مستقبلية

- عند اتخاذ قرار اختيار الـCloud Provider، يُنشأ ADR مستقل يوثق القرار وأسبابه.
- **لا يتم الاختيار النهائي لـCloud Provider قبل** توثيق Architecture الـBackend والـDatabase بشكل كامل.

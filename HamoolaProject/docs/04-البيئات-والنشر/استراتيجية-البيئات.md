# 04 — البيئات والنشر: استراتيجية البيئات الثلاث

**الحالة:** معتمد

> **للقرار المعماري التفصيلي:** راجع `../02-القرارات-المعمارية/ADR-005-استراتيجية-البيئات.md`

---

## نظرة عامة

```
المطور → [Local] → [Staging] → [Production]
```

كل بيئة لها هدف مختلف، مستخدمون مختلفون، وبيانات مختلفة. الفصل بين البيئات ليس اختيارياً — هو شرط لضمان جودة المشروع وأمان البيانات.

---

## الفرق بين البيئات

| العنصر | Local | Staging | Production |
|---|---|---|---|
| **من يستخدمها** | المطور فقط | الفريق التقني + العميل | المستخدمون الحقيقيون |
| **البيانات** | تجريبية يدوية | Seed Data منظمة | بيانات حقيقية |
| **قاعدة البيانات** | محلية (Localhost) | سيرفر Staging مستقل | سيرفر Production مستقل |
| **الـAPI URL** | `http://localhost:xxxx` | `https://staging.hamoola.com` | `https://api.hamoola.com` |
| **الاستقرار المطلوب** | لا يُشترط | متوسط | عالٍ جداً |
| **الهدف** | التطوير والتجريب | الاختبار والمراجعة | الخدمة الفعلية |

---

## Local — التفاصيل العملية

- **الإعداد**: كل مطور يُعِد بيئته المحلية بنفسه.
- **قاعدة البيانات**: تعمل على الجهاز مباشرة أو عبر Docker Container.
- **الـConfiguration**: ملف `appsettings.Development.json` (لـBackend) أو متغيرات بيئة محلية.
- **لا يُشارك Connection String المحلي** في الكود أو Git.

---

## Staging — التفاصيل العملية

- **الهدف**: محاكاة بيئة الإنتاج بدقة لاكتشاف المشاكل قبل الإطلاق.
- **الوصول**: فريق التطوير + QA + العميل لمراجعة الميزات.
- **البيانات**: بيانات تجريبية منظمة (Seed Data) تمثل حالات استخدام حقيقية.
- **النشر**: يتم تلقائياً عند Merge على `main` عبر CI/CD.
- **لا توجد بيانات مستخدمين حقيقيين** في هذه البيئة أبداً.

### الفرق بين Staging وProduction

| Staging | Production |
|---|---|
| بيانات وهمية للاختبار | بيانات حقيقية للمستخدمين |
| يمكن Reset قاعدة البيانات | لا يتم Reset قاعدة البيانات |
| تُقبل بعض الـBugs غير الحرجة | Zero Tolerance للأخطاء الحرجة |
| يصل إليها الفريق الداخلي | يصل إليها الجمهور |
| نشر تلقائي بعد Merge | نشر بموافقة يدوية |

---

## Production — التفاصيل العملية

- **الوصول**: المستخدمون الحقيقيون فقط (عند الإطلاق الرسمي).
- **النشر**: يتطلب موافقة يدوية حتى بعد نجاح CI/CD Pipeline.
- **المراقبة**: Monitoring وAlerting مفعّلان دائماً (تفاصيلها لاحقاً).
- **النسخ الاحتياطية**: Daily Backups على الأقل.
- **البيانات الحساسة**: تُعامَل وفق معايير الأمان وحماية البيانات.

---

## قواعد صارمة (لا استثناء فيها)

```
❌ لا تخلط قواعد البيانات بين البيئات
❌ لا تستخدم بيانات Production في التطوير أو الاختبار
❌ لا تنشر مباشرة على Production دون المرور بـStaging
❌ لا تضع Credentials أو Secrets داخل الكود
✅ كل بيئة لها Connection String مستقل
✅ كل بيئة لها متغيرات بيئة (Environment Variables) مستقلة
✅ كل Deployment يسبقه تشغيل Tests ناجح
```

## Configuration في Flutter

```dart
// مثال على تحديد بيئة التشغيل في Flutter
// يتم تمرير البيئة عبر --dart-define عند البناء

// flutter build apk --dart-define=ENVIRONMENT=staging
// flutter build apk --dart-define=ENVIRONMENT=production

const String environment = String.fromEnvironment(
  'ENVIRONMENT',
  defaultValue: 'local',
);
```

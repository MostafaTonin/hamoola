# قرار معماري 003 — قاعدة البيانات المركزية

**الحالة:** معتمد (النوع العلائقي)، **قيد الدراسة** (المنتج المحدد)  
**التاريخ:** 2026-09-25

---

## السياق

مشروع حمولة يتعامل مع بيانات مترابطة ومعقدة: مستخدمون بأدوار متعددة، طلبات شحن، عمليات نقل، فواتير، تقارير. يحتاج النظام إلى قاعدة بيانات موثوقة تضمن تكامل البيانات (Data Integrity) وتدعم العلاقات المعقدة بين الكيانات.

---

## الخيارات التي تمت دراستها

- **Relational Database** (SQL Server / PostgreSQL) — قواعد بيانات علائقية تعتمد على الجداول والعلاقات.
- **MongoDB** — قاعدة بيانات Document-oriented غير علائقية.
- **هجين (Relational + NoSQL)** — استخدام قاعدتين لأغراض مختلفة.

---

## القرار

**قاعدة بيانات علائقية (Relational Database)** هي الاختيار المعتمد لمشروع حمولة.

- قاعدة البيانات المركزية هي **المصدر الوحيد للحقيقة (Single Source of Truth)** في النظام.
- المنتج المحدد (**SQL Server** أو **PostgreSQL**) **قيد الدراسة** ولم يُحسم بعد.

---

## السبب

1. **البيانات علائقية بطبيعتها** — العلاقة بين المستخدمين والطلبات والمركبات والفواتير تناسب النموذج العلائقي تماماً.
2. **تكامل البيانات** — Foreign Keys وConstraints تضمن صحة البيانات وتمنع التضارب.
3. **ACID Transactions** — ضرورية في العمليات المالية والمعاملات التجارية الحساسة.
4. **Entity Framework Core** يدعم الـRelational Databases بشكل ممتاز مع Migrations منظمة.
5. **استعلامات معقدة** — SQL يوفر قدرة استعلام مرنة وقوية مع Performance جيد عند الفهرسة الصحيحة.

---

## الآثار

- **تصميم قاعدة البيانات** سيعتمد على نموذج علائقي مع Code-First Migrations عبر EF Core.
- **جميع التغييرات في Schema** تمر عبر Migrations موثقة ومُعتمدة.
- **البيانات الحساسة** (كلمات المرور، بيانات الدفع) تُعامَل بحماية خاصة.
- أي إضافة لـNoSQL (مثل Redis للـCaching) تكون **إضافة مكملة** ولا تحل محل قاعدة البيانات الرئيسية.

---

## قاعدة صارمة

> **لا يتم إضافة MongoDB أو أي قاعدة بيانات غير علائقية كقاعدة بيانات رئيسية** إلا إذا ظهر سبب تقني حقيقي وموثق يبرر ذلك.

---

## البدائل المرفوضة

- **MongoDB كقاعدة أساسية**: البيانات في حمولة علائقية بطبيعتها وتتطلب Transactions. MongoDB ليست مناسبة كـPrimary Database لهذا النوع من البيانات.
- **هجين من البداية**: يزيد التعقيد في مرحلة مبكرة من المشروع دون مسوّغ تقني.

---

## ملاحظات مستقبلية

- **Redis** للـCaching وإدارة Sessions يمكن إضافته لاحقاً إذا ظهرت متطلبات أداء تستدعيه.
- **MongoDB** يمكن استخدامه لأغراض محددة مثل Logs أو Analytics إذا احتجنا لاحقاً، لكن لا يلمس البيانات التشغيلية الرئيسية.
- اختيار **SQL Server مقابل PostgreSQL** يُحسم عند بدء تطوير الـBackend، مع مراعاة تكاليف الترخيص والبيئة المستضيفة.

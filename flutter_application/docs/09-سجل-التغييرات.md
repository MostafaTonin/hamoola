### [2026-09-25] — إضافة قرارات معمارية لاستراتيجية Frontend و CI/CD

**نوع التغيير:** إضافة قرارات معمارية (ADRs)

**ما الذي تغير؟**
- إضافة `ADR-007-استراتيجية-بناء-الواجهة-الأمامية-أولاً.md` لاعتماد البدء بالواجهات وتجربتها قبل الـ Backend.
- إضافة `ADR-008-اعتماد-GitHub-Actions-للتكامل-والنشر.md` لاعتماد GitHub Actions كأداة CI/CD.

**لماذا؟**
لتوضيح تدفق العمل في المرحلة الحالية (Frontend-First) وتأكيد الآلية المستقبلية للأتمتة (CI/CD) قبل كتابة أي كود متأثر بذلك.

**الأثر على المشروع؟**
قرارات توثيقية وتنظيمية، لا تأثير فوري على الكود الحالي.

### [2026-09-25] — توثيق دورة نشر تطبيق الموبايل

**نوع التغيير:** إضافة توثيق

**ما الذي تغير؟**
إضافة وثيقة `دورة-نشر-تطبيق-الموبايل.md` لتوضيح مفاهيم Mobile Deployment وGoogle Play Tracks وStaging وProduction، وتوضيح الفرق بين Flutter App وBackend وDatabase وموقف المشروع من استخدام SQLite.

**لماذا؟**

**الأثر على المشروع؟**
لا تأثير على الكود أو الـDependencies أو الـUI. التوثيق فقط.

### [2026-09-25] — إنشاء نظام التوثيق الرسمي

**نوع التغيير:** إضافة (Documentation System)

**ما الذي تغير؟**
إنشاء مجلد `docs/` كامل بنظام توثيق رسمي يشمل:
- دليل التوثيق (كيفية الاستخدام).
- نظرة عامة على المشروع.
- 6 وثائق ADR للقرارات المعمارية الأساسية.
- نظام التسمية الموحد (Naming Conventions).
- سياسة إدارة الكود (Git / GitHub Flow).
- استراتيجية البيئات الثلاث (Local / Staging / Production).
- وثيقة نظام التصميم.
- وثيقة معمارية تطبيق Flutter.

**لماذا؟**
لضمان أن كل قرار هندسي مهم موثق، وأن أي عضو جديد في الفريق يستطيع فهم المشروع دون الاعتماد على الذاكرة أو المحادثات.

**الأثر على المشروع؟**
لا تأثير على الكود أو الـDependencies أو الـUI. التوثيق فقط.

**المرجع:** لا يوجد ADR — هذا قرار تنظيمي بإضافة نظام التوثيق.
